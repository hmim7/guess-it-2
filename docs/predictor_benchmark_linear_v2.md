# Linear-v2 Predictor — Head-to-Head Benchmark

Branch: `linear-v2` (cut from `linear`). Generated by `bash _sim/headtohead.sh`
under WSL, against the dockerized opponents on `data_sets/4` and `data_sets/5`.

## Change vs `linear` baseline

Single change: the centre estimator now comes from a **running OLS over the
entire prefix** (`linearstats.RunningOLS`) once `seen ≥ 30`, instead of the
20-point window regression for the first 1,000 samples + window median after.
The ±20 half-width is unchanged. For samples < 30 the predictor falls back to
the original `Predict(window, seen, current)` so non-linear datasets and the
warm-up phase are untouched.

Why this helps: the original window median on slope-1 data estimates `y_{n-10}`
rather than `y_{n+1}` (a ~10-unit bias), and the 20-point regression has noisy
slope/intercept after just 20 samples. A running OLS is unbiased and stabilises
within ~30 samples for the linear-trend Data 4 / Data 5 streams.

## Files changed

- [linearstats/stats.go](linearstats/stats.go) — added `RunningOLS` struct.
- [linearstats/predict.go](linearstats/predict.go) — added stateful `Predictor`
  with `NewPredictor()` + `Next(current)`; original `Predict(window, seen, current)`
  retained as the cold-start fallback.
- [main.go](main.go) — uses `linearstats.NewPredictor()` and `p.Next(v)` per input.
